# 投稿型懐古アプリ (位置情報連動型メディアログ)
稼働URL:https://muds.gdl.jp/~s2422073/login.php

（＊loginは、ユーザー名：r,パスワード：rで可能。新規登録でも可能です。）

位置情報と動的なメディア（画像・テキスト）を連動させ、特定の場所における「ユーザーの思い出（ログ）」を非同期かつ動的に共有・閲覧できるWebアプリケーションです。

## 🚀 プロダクトの核 (Why・How・Fact)

### 🔴 【Why】解決する課題
タイムライン形式で情報が刹那的に流れていく一般的なSNSとは異なり、「その場所（位置情報）に紐づく過去の記憶や風景」をストック・可視化します。特定の地域やスポットが持つ歴史的・個人的な価値（懐古ログ）を直感的に掘り起こせる空間主導型のメディアプラットフォームを目指しました。

### 🛠️ 【How】技術選定とWeb標準へのアプローチ
フレームワークによる隠蔽（ブラックボックス化）を避け、Webアプリケーションの標準的なアーキテクチャとデータフローを深く理解するために、あえてネイティブな技術スタックを採用しました。

* **Backend / Logic:** PHPを用いた、サーバーサイドでの動的なコンテンツ生成（SSR）。セッション管理やユーザーリクエストに応じた動的なHTMLレンダリングの仕組みを実装。
* **Database / Storage:** PostgreSQL（RDBMS）による構造化データの管理。ユーザー情報、投稿テキスト、および位置情報（座標データ）のテーブル設計を行い、効率的なSQLクエリ発行によってデータを紐付け。
* **Frontend / Interaction:** HTML5 / CSS3 によるレイアウト構築に加え、JavaScriptを採用。掲示板としての動的なメディア表示、ナビゲーション、およびインタラクティブなユーザー体験（UI操作）の制御を担当。
* **AI-Driven Development:** プロトタイプ段階でのSQLクエリの最適化や、PHPでのエッジケース（バリデーションやセキュリティ対策の思想）の壁打ち相手としてLLMを活用し、実装の高速化を担保。

### 🏆 【Fact】客観的成果
* 大学のサーバー環境（muds.gdl.jp）へ本番デプロイを完遂し、実ホスティング環境での動作を確認済み。
* フロントエンド（JS/CSS）からバックエンド（PHP）、データベース（PostgreSQL）に至るWebアプリケーションの「3層アーキテクチャ」の基本フローを完全ワンオペで構築。

## 🧠 未来の自分への設計メモ（Why＆思考一覧）

数ヶ月後の自分が「設計の割り切り」を10秒で思い出すためのカンペ。

### 1. なぜ「あえて」生のPHP × PostgreSQLなのか？
* **Why:** Laravel等のモダンフレームワークに隠蔽された、HTTPプロトコル、セッション管理、生のSQL、CRUD制御といった「Webアプリケーションの低レイヤの原理原則」を体感として理解・検証するため。
* **トレードオフ:** セキュリティ（XSS、SQLインジェクション等）をフレームワーク任せにできず、すべて自前で防御コードを書く必要があり、開発速度が犠牲になる。

### 2. ユーザー・データが10倍になったらどこが壊れるか？
* **位置情報検索の窒息:** 「近くの思い出」を緯度・経度の単純な大小比較（`BETWEEN`クエリ等）でやっている場合、データ増大でインデックスが効かなくなり、フルテーブルスキャンでDBが死ぬ。
  * *対策:* PostgreSQLの地理空間拡張である「PostGIS」を導入し、幾何学的なGISTインデックス（R-tree構造）を用いた空間クエリへ移行する。
* **メディアファイルによるストレージ・帯域の破綻:** 画像や動画などの動的メディアをDB内に直接保存（BLOB）、またはWebサーバーのローカルにそのまま置いている場合、アクセス増大でディスクI/Oとネットワーク帯域がパンクする。
  * *対策:* メディアファイルをAWS S3等のオブジェクトストレージに分離し、CDN（CloudFront等）を前段に挟んで配信負荷をサーバーから引き剥がす。

### 3. 思考壁打ち
* **Q. 「フレームワークを使わないとセキュリティが脆弱になりがちだけど、どう対策した？」**
  * *A.* 「入力層ではPDOのプリペアドステートメント（プレースホルダー）を徹底してSQLインジェクションを100%排除し、出力層ではすべての動的テキストに `htmlspecialchars()` を通してXSS（クロスサイトスクリプティング）を防御しています。フレームワークを剥ぎ取ったからこそ、Web脆弱性の本質的な防ぎ方が血肉化できました」
